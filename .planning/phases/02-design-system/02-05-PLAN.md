<objective>
Replace native HTML `<button>` elements with the design system `<Button>` component across the codebase.

Purpose: Native `<button>` elements bypass the design system's visual treatment (custom cursors, audio hover effects, PrimeVue integration, consistent styling). Replacing them ensures interactive elements look and behave consistently. This is moderate-risk work since `<Button>` has different behavior than native `<button>` (wraps PrimeVue, includes Control wrapper).

Output: 5 user-facing files with native buttons replaced, 2 design system internals evaluated.
</objective>

  <action>
For each file, find native `<button>` elements and replace with the design system `<Button>` component.

**Replacement steps:**
1. Search for `<button` in the `<template>` section
2. For each native button:
   a. Replace `<button` with `<Button` and `</button>` with `</Button>`
   b. Preserve all `@click` (and other event) handlers — they work the same on `<Button>`
   c. Replace custom CSS classes with Button variant classes:
      - Background color styling → use `green`, `red`, `blue`, `black`, or `grey` class
      - Size styling → use `slim` or `large` class
      - Width → use `fullwidth` class
   d. Remove the custom CSS rules that styled the native button (padding, font-size, background, border, hover states) — the `<Button>` component handles all of this
3. Add the import if not already present:
   ```
   import Button from "@renderer/components/controls/Button.vue";
   ```
   Note: With `<script setup>`, importing makes it available in the template.

**Key considerations:**
- `index.vue` has 2 buttons — likely the main login/play buttons. Map to appropriate color variants (e.g., `green` for primary action).
- `Messages.vue` has 3 buttons — likely message action buttons (reply, close, etc.). Use `slim` for compact actions.
- `PlayerParticipant.vue` has 1 button — check if it's a kick/action button
- `TeamComponent.vue` has 2 buttons — team management actions
- `BotParticipant.vue` has 2 buttons — bot management actions (add/remove)

**Risk mitigation:** After replacement, verify:
- Click handlers still fire
- Button text/icon content renders correctly
- No CSS rules reference the old `.custom-button-class` that no longer exists
